N-gram analysis

Every search term is broken into 1-, 2- and 3-word fragments, then spend/clicks/orders are aggregated per fragment across the whole dataset. A single bad word can hide inside dozens of search terms — this catches the pattern in one pass instead of negating terms one at a time. Any fragment that also appears in a converting term is marked Protected — never negate a token without checking this column first (this is exactly the "vegan" trap from the practical task).

Automate & export

Bundles every recommendation currently on screen (bids, harvest, negation, N-gram flags, dayparting) into one JSON payload — the same shape a Make.com or n8n scenario would receive from a webhook trigger and route to its Amazon Ads HTTP modules.

Browsers block cross-origin POST requests that a receiving server doesn't explicitly allow (CORS). Make.com and n8n webhooks usually accept this fine, but if "Send" fails, use Download JSON and drop the file into an HTTP/Webhook module manually — same data, just pasted instead of posted.

Prompt library

  
Reusable prompts for the AI step inside your Make.com/n8n scenario (an OpenAI/Claude/Anthropic
  module) — or paste these into a Notion database as your standing prompt reference. Each one bakes in a
  guardrail so the model can't make the same mistakes the practical task caught.


  

    
1. Harvest candidates from a search-term report

    
You're analyzing an Amazon Sponsored Products search-term report for [brand/account].
Product catalog with SKUs and what each one is: [paste list].
Known ambiguous or overlapping terms in this catalog: [e.g. "backen/baking" = food-grade SKU, "vegan" = converts on powder SKU].

From the attached report, identify search terms that are candidates to harvest to their own exact-match keyword.
A candidate must have: >=2 orders in the trailing 90 days (not 30), an ACoS at or better than [target]%,
and not already exist as its own keyword.

For each candidate, show: the term, orders, ACoS, current matched product, and your confidence.
Do not recommend harvesting a term matched to a SKU you're not certain about — flag it as "needs human check" instead of guessing.
Do not aggregate or generalize across terms — evaluate each one on its own row of data.
Output as a table only, no narrative summary.

    
  


  

    
2. Cross-check a negation list before it goes live

    
You will review a list of search terms proposed for negation. Before agreeing with ANY of them,
cross-reference each term (and every individual word inside it) against the attached 90-day converting-terms list.

Rules:
- If the exact term appears in the converting list, mark REJECT and state the orders/ACoS you found.
- If a single word from the term appears inside a DIFFERENT converting term, mark REJECT for any
  broad/phrase-level negation of that word alone, and explain which converting term it would also block.
- If the term has 0 orders in both the 30-day and 90-day windows and is semantically unrelated to
  every SKU in [catalog list], mark APPLY.
- If the term has some orders but at an ACoS far above target, mark ADJUST and recommend a bid change
  instead of a block.

Output one row per term: term, your verdict, the specific data point that justifies it.

    
  


  

    
3. Weekly N-gram spend audit

    
From the attached search-term report, break every search term into 1-, 2- and 3-word fragments
and aggregate clicks, spend, orders and sales per fragment across the whole account.

Return only fragments where: spend >= [$X] AND orders = 0.
For each, list every full search term that contains it, so I can see what else a negation of
that fragment would affect. If a flagged fragment also appears in ANY term with orders > 0
anywhere in the last 90 days, label it "DO NOT NEGATE — appears in a converting term" instead
of listing it as a candidate.

    
  


  

    
4. Dayparting recommendation from hourly data

    
From the attached hour-by-hour clicks/orders/spend data (last [30/90] days, summed by hour of day),
calculate CVR per hour and compare it to the account's daily average CVR.

Recommend a bid multiplier per hour using these bands: below [70]% of average CVR -> suppress
multiplier, above [130]% of average CVR -> boost multiplier, otherwise hold at 1.0x.
Flag any hour where the sample size (clicks) is too small to be reliable (fewer than [20] clicks)
instead of assigning it a confident multiplier.

    
  


  

    
5. Weekly account health check (TACoS/ACoS)

    
Given this account's last 30 days of campaign, ad group and keyword-level spend/sales/orders,
and last 30 days of organic sales (non-ad), calculate TACoS and break down whether any change
versus the prior 30 days is driven by ad spend, ad efficiency, or organic sales movement.

Identify the 5 highest-spend, highest-ACoS keywords driving the gap to target. For each, state
whether the right lever is: bid reduction, negation (only if 0 orders across 90 days), dayparting,
or budget/placement review. Do not recommend pausing a campaign entirely unless every keyword
in it individually fails the same check.

The module-by-module shape of the automation — this is exactly what should sit
  inside the router's branches, using the payload from the Automate tab as the trigger data.

→

→

BRANCH A · BID

Log to Google Sheets

    
BRANCH B · HARVEST
